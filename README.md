# fk-linux-cve

Daily GitHub Actions build of the latest kernel.org kernels as `.deb` and `.rpm` packages, published as GitHub releases.

## What gets built

`.github/workflows/kernel-build.yml` runs daily (01:30 UTC) and on manual dispatch:

1. **check** — `scripts/check-releases.sh` reads <https://www.kernel.org/releases.json>, takes every `mainline`, `stable` and `longterm` entry that is not EOL, and drops versions that already have a published release tagged `v<version>`. Already-built versions are never recompiled.
2. **build** — one matrix job per remaining version: `scripts/install-build-deps.sh`, then `scripts/build-kernel.sh` (`make bindeb-pkg` + `make binrpm-pkg`), then `gh release create v<version>` with all packages, the final `.config` and `SHA256SUMS`.

Both jobs run on the self-hosted runner label `yesong-lab` inside a `debian:trixie` container (GCC 14, ships both `dpkg-dev` and `rpmbuild`). The runner must support container jobs (Docker installed) and have roughly 30 GB free disk per concurrent build.

Release conventions:

| moniker  | tag example  | GitHub flags                         |
| -------- | ------------ | ------------------------------------ |
| mainline | `v7.4-rc3`   | prerelease                           |
| stable   | `v7.3.5`     | marked Latest (newest stable only)   |
| longterm | `v6.12.118`  | not Latest                           |

A failed build publishes nothing, so the version is retried on the next run. Interrupted uploads leave only a draft, which does not count as built and is deleted before the retry publishes.

## Kernel config

Base: Fedora rawhide's `kernel-x86_64-fedora.config` from <https://src.fedoraproject.org/rpms/kernel>, downloaded at build time (override with `BASE_CONFIG_URL`). Rawhide tracks mainline closely, so few symbols are new to it. `configs/fragment.config` is merged on top, then `make olddefconfig` fills in defaults for anything the base lacks (Rust is dropped automatically since the container has no rustc). The fragment:

- clears signing certificate paths; modules are signed with a per-build autogenerated key, so **Secure Boot with enforced signature checks will reject these kernels**;
- disables debug info (and therefore BTF);
- disables `CONFIG_WERROR`.

Edit `configs/fragment.config` to customize.

## Install

```sh
# Debian / Ubuntu
sudo apt install ./linux-image-*.deb ./linux-headers-*.deb
# Fedora / RHEL / openSUSE
sudo dnf install ./kernel-*.rpm
```

## Local build

```sh
podman run --rm -it -v "$PWD":/repo debian:trixie bash -c \
  '/repo/scripts/install-build-deps.sh && /repo/scripts/build-kernel.sh 6.12.118 https://cdn.kernel.org/pub/linux/kernel/v6.x/linux-6.12.118.tar.xz /repo/out'
```
